## 0. 這份文件怎麼讀

這份文件不是功能清單，是**操作情境的逐步還原**。

- **User Scenarios** 是主體：七個情境按交付優先序排成 P1～P3，每個都可獨立驗收。想快速理解系統，只讀這一段。
- **Requirements** 把行為攤成 FR-xxx，並對應到原規則編號 R-xx（[spec-screens.md](spec-screens.md) 仍以 R-xx 引用，編號不變）。
- **Success Criteria** 是可量測的驗收門檻，與技術實作無關。
- **附錄 A** 是情境的逐步敘事全文，可直接拿著對螢幕做 demo。
- **附錄 B** 是規則、狀態機、資料模型、權限矩陣，給客戶的技術窗口或 IT 主管查驗。
- **Out of Scope** 明確列出本版不做的事，避免售前承諾與實際交付出現落差。

業務端讀 User Scenarios + 附錄 A 即可，不需要讀附錄 B。

### 產線與角色設定

本文件用兩條真實存在上下游關係的產線來說明，目的是證明：**同一套系統可以承載工序數量不同、檢驗方式不同、記錄欄位完全不同的兩條線，而不需要為第二條線改程式。**

**產線 A：金屬前框沖焊線** — 生產 27 吋監視器用的金屬外框。特徵是工序線性、有中間品檢、不合格會退回重做。

```
薄板沖壓 → 沖壓品檢 → 雷射焊接 → 清洗 → 成品品檢
```

| 工序 | 站點 | 類型 | 作業員 | 是否回報數量 |
| --- | --- | --- | --- | --- |
| 薄板沖壓 | 沖壓線 | 生產 | 王沖壓 | 是 |
| 沖壓品檢 | 沖壓品檢站 | 品檢 | 李檢驗 | 否（回報判定結果） |
| 雷射焊接 | 雷射焊接站 | 生產 | 陳焊接 | 是 |
| 清洗 | 清洗站 | 生產 | 林清洗 | 否 |
| 成品品檢 | 成品品檢站 | 品檢 | 李檢驗 | 否（回報判定結果） |

代表工單：`MO-FR-27-005`，產品 `FR-27-BZ-A`（27 吋監視器用金屬前框），數量 10,000 個。

**產線 B：監視器整機組裝線** — 生產 27 吋監視器整機。特徵是投入料件來自產線 A、含機台自動測試、檢驗要拍照存證。

```
前框上料組裝 → 電控模組安裝 → 功能測試 → 外觀檢驗 → 包裝入庫
```

| 工序 | 站點 | 類型 | 作業員 | 特殊性 |
| --- | --- | --- | --- | --- |
| 前框上料組裝 | 組裝一線 | 生產 | 張組裝 | 投入產線 A 的成品 |
| 電控模組安裝 | 組裝二線 | 生產 | 黃組裝 | — |
| 功能測試 | 測試房 | 品檢 | 測試治具 + 周測試 | 機台自動帶入量測值 |
| 外觀檢驗 | 目檢站 | 品檢 | 吳目檢 | 需拍照存證 |
| 包裝入庫 | 包裝線 | 生產 | 蔡包裝 | 完工即入庫 |

代表工單：`MO-MON-27-011`，產品 `MON-27-A`（27 吋監視器整機），數量 2,000 台。

**兩線的銜接關係：** 產線 A 的 `MO-FR-27-005` 完工入庫後，其成品 `FR-27-BZ-A` 成為產線 B `MO-MON-27-011` 第一站「前框上料組裝」的投入料件。這代表 **產線 A 的品檢判定，會直接決定產線 B 能不能開工**。這一點在 User Story 4 會實際演到。

**角色：**

| 角色 | 誰 | 主要畫面 | 能做什麼 |
| --- | --- | --- | --- |
| 現場作業員 | 王沖壓、陳焊接等 | 工位終端 | 開始 / 完成自己站點的工序，填寫該站欄位 |
| 檢驗員 | 李檢驗、吳目檢 | 工位終端（品檢模式） | 判定合格 / 不合格，分流數量，填不良代碼 |
| 線長 / 班長 | 產線負責人 | 狀態板 + 工單詳情 | 看全線狀態，處理報廢審核 |
| 廠內流程管理員 | 製造部或品保部指定人員 | 系統設定 | **動態新增 / 調整記錄欄位，不需 IT 介入** |

### User Story 1 — 工單一站一站自動推進 (Priority: P1)

作業員站在工位終端前，終端已經停在他這一站，待辦清單上就是現在該做的那張單。他按「開始」，做完按「完成」，填完這一站被設定過的欄位送出。單子自動出現在下一站的待辦清單上，**沒有人需要通知下一站，也沒有人需要把單子拿過去**。五站依序走完，最後一站品檢合格後工單自動結案。

**Why this priority**: 這是整套系統的骨架。沒有這條路，其餘六個情境都無處附著。它同時證明了對客戶最有感的一件事——現場全程只按「開始 / 完成」，不需要理解系統，也不需要維護 Excel。

**Independent Test**: 只實作這一條路即可完整驗收：在產線 A 建一張 10,000 個的工單，由五個站點的終端依序走完，確認每一站完成後單子自動出現在下一站待辦、狀態板同步更新、最終工單結案。此時系統已可對客戶展示核心價值。

**Acceptance Scenarios**:

1. **Given** `MO-FR-27-005` 尚未開工、終端停在「沖壓線」，**When** 王沖壓看待辦清單，**Then** 清單只有一行且狀態為「可開始」，工序卡顯示「本關：薄板沖壓／上一關：無／下一關：沖壓品檢／狀態：尚未開始」，只有「開始」可按、「完成」為灰。
2. **Given** 工序卡狀態為「尚未開始」，**When** 王沖壓按「開始」，**Then** 系統回「本關進行中。作業員：王沖壓。開始：08:12:30」，工序卡轉「進行中」，「完成」亮起、「開始」變灰，狀態板同步顯示「這批現在在薄板沖壓，王沖壓作業中」。
3. **Given** 工序卡為「進行中」，**When** 王沖壓按「完成」，**Then** 系統跳出該站被設定過的回報表單（實際沖壓數／模具編號／料捲批號／備註），而非寫死的固定表單。
4. **Given** 回報表單必填欄位皆已填妥，**When** 王沖壓送出，**Then** 系統回「本關已完成。下一關是『沖壓品檢』，由『沖壓品檢站』開始」，工序卡轉「已完成」，該單從王沖壓的待辦清單消失。
5. **Given** 薄板沖壓已完成，**When** 沖壓品檢站的終端刷新待辦，**Then** 該單自動出現且狀態為「可開始」，過程中無人手動通知或轉派。
6. **Given** 終端為品檢站，**When** 李檢驗開啟工序卡，**Then** 卡上沒有「完成」按鈕，取而代之的是「合格 / 不合格」兩顆。
7. **Given** 沖壓品檢進行中，**When** 李檢驗填妥抽檢數 200、平面度 0.21、判定合格、合格數 10,000、重工數 0、報廢數 0 並送出，**Then** 系統回「沖壓品檢合格。下一關是『雷射焊接』。工單尚未結束」。
8. **Given** 前四站皆已完成，**When** 李檢驗在成品品檢判定合格，**Then** 系統回「成品品檢合格。工單已結束」，狀態板顯示「五關完成。工單已結束」。
9. **Given** 任一站的作業員操作全程，**When** 檢視其操作步驟，**Then** 他未曾選擇工單、未曾輸入工號、未曾查詢今日工作內容。

### User Story 2 — 跳站在當下被擋住 (Priority: P1)

沖壓才剛完成、還沒品檢。陳焊接想先把焊接站的機台暖起來，跑到雷射焊接站終端按「開始」。系統當場拒絕並指名需先完成哪一站，**工單狀態完全沒有改變，沒有任何紀錄被寫進去，狀態板也沒有跳動**。

**Why this priority**: 這是客戶最在意的「系統到底控不控得住」的第一個證明點。跳站在這套系統裡不是違規，是**不存在的操作**——不是事後稽核發現有人跳站，是當下就按不下去。

**Independent Test**: 在 User Story 1 的基礎上，於前置工序未完成時到後段站點按「開始」，確認被拒、確認拒絕訊息指名了需先完成的工序、確認工單狀態與狀態板皆無變化、確認資料層無新增任何紀錄。

**Acceptance Scenarios**:

1. **Given** 薄板沖壓已完成但沖壓品檢未完成，**When** 陳焊接查看雷射焊接站待辦清單，**Then** 該單顯示狀態「還不能開始」。
2. **Given** 該單在焊接站狀態為「還不能開始」，**When** 陳焊接按「開始」，**Then** 系統回「還不能開始。需先完成『沖壓品檢』。」，訊息中指名了具體的前置工序名稱。
3. **Given** 前述拒絕已發生，**When** 檢視工單狀態、各站狀態與狀態板，**Then** 三者與按下按鈕之前完全一致，未新增任何工序紀錄。
4. **Given** 產線 B 的工序順序與產線 A 完全不同，**When** 在產線 B 執行相同的跳站測試，**Then** 阻擋行為一致，且被指名的前置工序來自產線 B 自己的製程定義，證明順序非程式寫死。

### User Story 3 — 品檢不合格，退回重做且舊紀錄留得住 (Priority: P1)

李檢驗抽檢發現平面度超標，按「不合格」。表單長出只在不合格時才出現的欄位（不良代碼、退回工序）。送出後被退回的工序回到「可重做」，後段工序**維持鎖住**。王沖壓換一副模具重做，再次送檢通過，流程回到正軌。工單完成後，追溯畫面上看得到「第 1 次沖壓」與「第 2 次沖壓」兩筆完整紀錄，**不是覆蓋**。

**Why this priority**: 這是整份規格最重要的一段，也是客戶買 MES 真正想要的東西。不是報表好看，是出事時能在三十秒內指出是哪一批料、哪一副模具、哪一個人、哪一個時段。

**Independent Test**: 走完一次「不合格 → 退回 → 重做 → 合格」的循環，確認退回瞬間各站狀態轉移正確、後段從未被解鎖、兩次沖壓的模具編號與料捲批號皆完整保留且可在同一頁比對。

**Acceptance Scenarios**:

1. **Given** 沖壓品檢進行中，**When** 李檢驗選擇判定「不合格」，**Then** 表單出現「不良代碼」（不合格時必填）與「退回工序」（必填），且退回工序的可選範圍僅限本站之前的生產工序。
2. **Given** 判定不合格、不良代碼 DEF-FLAT、重工數 10,000、退回工序「薄板沖壓」，**When** 送出，**Then** 系統回「判定不合格。工單不能結束。請退回『薄板沖壓』重做。焊接尚未開始。」
3. **Given** 退回已生效，**When** 檢視五站狀態，**Then** 薄板沖壓由「已完成」轉為「可重做」並回到待辦清單；沖壓品檢轉為「不合格」；雷射焊接、清洗、成品品檢**維持**「還不能開始」。
4. **Given** 退回已生效，**When** 檢視後段三站的狀態變更歷程，**Then** 它們從未被解鎖過，因此不需要任何「取消」或「回收」動作。
5. **Given** 王沖壓第一次填寫的模具 MD-FR27-02 與料捲 RC-20260815-A 已存在，**When** 他以模具 MD-FR27-05 重做並送出，**Then** 系統新增「第 2 次」紀錄，第 1 次的所有欄位值完整保留未被修改。
6. **Given** 工單已完工，**When** 開啟追溯畫面，**Then** 可在同一頁看到每一站的次數、時段、作業員與該站欄位值，包含兩次沖壓的模具差異與兩次品檢的平面度差異（0.52 不合格 / 0.19 合格）。

### User Story 4 — 數量分流：合格、重工、報廢三條路 (Priority: P2)

不是所有不合格都要重做。李檢驗在沖壓品檢發現 10,000 個裡有一部分邊緣毛邊嚴重、無法重工，於是把數量分成合格 9,200、重工 500、報廢 300。系統驗證三者加總必須等於送檢數，然後把工單拆成兩條並行推進線：**主批不需要等重工批**，可以直接往下走。這張單的完工數會是 9,700 而不是 10,000，而這個短缺會直接影響下游產線 B 能不能開工。

**Why this priority**: P1 三項證明了流程控得住，這一項證明了**數量算得準**。產能與成本的說服力來自這裡，而跨工單料件短缺的控管是「只買現場報工」看不到的一層。但它建立在 User Story 3 的退回機制之上，因此排在 P2。

**Independent Test**: 在品檢站做一次三向分流，確認加總驗證會擋、確認主批不等重工批即可推進、確認完工數等於主批合格數加重工批最終合格數、確認下游工單在料件不足時第一站被擋。

**Acceptance Scenarios**:

1. **Given** 送檢數 10,000，**When** 李檢驗填入合格 9,200、重工 500、報廢 200（加總 9,900），**Then** 送出被阻擋且畫面上標紅，提示加總必須等於送檢數。
2. **Given** 報廢數大於 0，**When** 檢驗員未填「報廢原因」即送出，**Then** 被阻擋，報廢原因為必填。
3. **Given** 分流為合格 9,200、重工 500、報廢 300 且加總正確，**When** 送出，**Then** 狀態板同時顯示兩行：「主批 9,200 個現在可到雷射焊接」與「重工批 500 個現在在薄板沖壓，尚未開始」。
4. **Given** 重工批尚未開始重做，**When** 陳焊接在雷射焊接站對主批按「開始」，**Then** 允許開始，主批不需等待重工批。
5. **Given** 主批當前在清洗、重工批完成沖壓品檢，**When** 重工批併回，**Then** 併回起點為主批當前工序的前一站（雷射焊接）。
6. **Given** 主批合格 9,200、重工批最終全數合格 500，**When** 工單結案，**Then** 完工數量為 9,700，報廢 300 的成本仍歸屬於本工單、未從帳上消失。
7. **Given** `MO-FR-27-005` 完工 9,700 個而產線 B 需求 2,000 個，**When** 張組裝在「前框上料組裝」按「開始」，**Then** 允許開始（庫存足夠）。
8. **Given** 可用量降為 1,800 個而產線 B 需求 2,000 個，**When** 張組裝按「開始」，**Then** 系統回「還不能開始。料件 FR-27-BZ-A 可用量 1,800，需求 2,000，短缺 200。」

### User Story 5 — 報廢超過門檻須主管核准 (Priority: P2)

成品品檢時發現整批鍍層附著力不合格，全數無法出貨。檢驗員填入報廢 9,700，但系統這次不是直接結案，而是判定超過本工單允收上限並送出審核，工單暫停於「成品品檢」。線長在待審清單看到這一筆，點進去看得到完整追溯紀錄，可核准也可駁回；駁回時工單退回品檢站重新判定。

**Why this priority**: 報廢是有金額的。低於門檻由檢驗員當場決定，超過門檻必須有人簽字——而**門檻是廠內管理員可以設定的數字，不是寫死的**。這一層是財務與品保會問的問題，但不影響現場流程能否跑通，因此排在 P2。

**Independent Test**: 製造一筆超過門檻的報廢，確認工單進入待審而非結案、確認線長待審清單可見且附完整追溯、確認核准與駁回兩條路徑皆正確、確認門檻百分比可由管理員調整並立即生效。

**Acceptance Scenarios**:

1. **Given** 報廢佔比超過設定門檻（預設 5%），**When** 檢驗員送出判定，**Then** 系統回「報廢數 9,700 已超過本工單允收上限（5%）。已送出報廢審核，待『線長』核准後生效。工單暫停於『成品品檢』。」，工單未結案。
2. **Given** 報廢審核已送出，**When** 線長開啟待審清單並點入該筆，**Then** 可看到完整追溯紀錄，包含各站作業員、模具、料批與每一站的量測值。
3. **Given** 線長核准，**When** 送出核准，**Then** 系統回「報廢審核已核准。工單 MO-FR-27-005 結案，完工數量 0，報廢 9,700。」
4. **Given** 線長駁回並填理由「建議先送重工評估」，**When** 送出駁回，**Then** 系統回「報廢審核已駁回。理由：建議先送重工評估。工單退回『成品品檢』，請重新判定。」，該單回到李檢驗的待辦。
5. **Given** 管理員將門檻由 5% 調整為 10%，**When** 新的品檢判定報廢佔比為 7%，**Then** 不觸發審核，直接生效。

### User Story 6 — 第二條產線零改程式上線 (Priority: P2)

張組裝在組裝一線的終端，看到的畫面結構跟王沖壓在沖壓線看到的**完全一樣**：待辦清單、工序卡、開始 / 完成按鈕。他不需要重新學。差別全部在按下「完成」之後跳出來的表單——產線 A 記的是模具、料捲、平面度；產線 B 記的是治具報告、亮度、色差、照片。**兩條線用的是同一份程式碼。**

**Why this priority**: 這是「同一套系統」這句承諾的證明。對售前極重要，但它驗證的是既有機制的通用性而非新增能力，因此排在 P2。它依賴欄位設定的資料模型已經存在（即 User Story 7 的資料層，但不需要 User Story 7 的管理介面）。

**Independent Test**: 建立產線 B 的製程定義與欄位設定，不修改任何元件程式碼即讓產線 B 上線並走完五站，確認畫面骨架與產線 A 一致而表單內容完全不同。

**Acceptance Scenarios**:

1. **Given** 終端切換至產線 B 的組裝一線，**When** 張組裝檢視畫面，**Then** 待辦清單、工序卡、按鈕的版面與產線 A 完全一致，僅站名與工序名不同。
2. **Given** 前框上料組裝站，**When** 張組裝按「完成」，**Then** 表單為完成台數（數字，必填）／前框批號（單選，自動帶入可用批號，必填）／面板批號（文字，必填），與產線 A 任一站的表單皆不同。
3. **Given** 功能測試站且治具已回傳量測值，**When** 周測試開啟表單，**Then** 測試報告編號、亮度、色差、判定皆已由治具自動填入，他只需確認送出。
4. **Given** 治具量測值超出設定範圍（例如亮度 480 超出 350–450），**When** 表單載入，**Then** 判定自動帶為「不合格」。
5. **Given** 判定被治具自動帶為「不合格」，**When** 周測試將其覆寫為「合格」，**Then** 系統要求填寫覆寫理由，未填不得送出。
6. **Given** 外觀檢驗站判定為不合格，**When** 吳目檢送出，**Then** 缺陷代碼與缺陷照片皆為必填，照片可拍多張且與本次檢驗紀錄綁定。
7. **Given** 產線 B 已上線，**When** 檢視版本控制的變更範圍，**Then** 改動僅涉及製程定義與欄位設定資料，未修改 `src/components/` 或 `src/pages/` 下的任何元件程式碼。

### User Story 7 — 管理員三分鐘自助新增記錄欄位 (Priority: P3)

品保部要求從下週起雷射焊接站要記錄氬氣流量。在沒有 MES 的工廠，這件事是「印一張新表格發下去」；在寫死欄位的系統，這件事是「開需求單給供應商，等下一版」。在這套系統，廠內流程管理員自己進系統設定填六格欄位定義，按儲存，**全程約三分鐘，沒有開需求單，沒有重新部署，沒有系統停機**。下一位在該站按「完成」的作業員就會看到新欄位。

**Why this priority**: 這是客戶問「以後我們自己改得動嗎」時要當場演的一段，也是長期維運成本的關鍵。但它是管理端能力，不影響現場流程能否跑通，因此排在 P3。

**Independent Test**: 以管理員身分新增一個帶有效範圍的必填數字欄位，計時全程；接著在該站按完成，確認新欄位出現、必填生效、超範圍被擋；再確認設定前已完成的歷史紀錄不受影響。

**Acceptance Scenarios**:

1. **Given** 管理員在系統設定 → 記錄欄位 → 選擇「雷射焊接」，**When** 填入欄位代碼 `argon_flow`、顯示名稱「氬氣流量 (L/min)」、型別數字、必填是、適用工序雷射焊接、有效範圍 12～20 並儲存，**Then** 儲存成功，全程不需重新部署或系統停機。
2. **Given** 新欄位已啟用，**When** 陳焊接在雷射焊接站按「完成」，**Then** 表單多出「氬氣流量 (L/min)」一格並標示必填。
3. **Given** 新欄位為必填，**When** 陳焊接未填即送出，**Then** 被阻擋。
4. **Given** 有效範圍為 12～20，**When** 陳焊接填入 25，**Then** 系統回「氬氣流量 25 超出有效範圍 12 ~ 20。」並阻擋送出。
5. **Given** 新欄位設定前已完成的工序紀錄，**When** 檢視該紀錄，**Then** 該欄位顯示「—」，且**不被追認為缺漏**。
6. **Given** 管理員事後將該欄位改為非必填，**When** 檢視已存的歷史值，**Then** 歷史值完整保留，變更僅影響之後的紀錄。
7. **Given** 管理員事後停用該欄位，**When** 檢視新表單與歷史紀錄，**Then** 新表單不再出現此欄，歷史紀錄與報表仍可查，欄位未被刪除。
8. **Given** 欄位已啟用一段時間，**When** 查詢追溯報表，**Then** 該欄位可查、可匯出、可與不良率交叉分析。

### Edge Cases

以下情況已識別但**尚未在規格中定義行為**，逐項對應 Requirements 中的 `[NEEDS CLARIFICATION]` 標記：

- 報廢門檻百分比的分母是工單總數還是本次送檢數？多次報廢是否累計計算？（CL-002）
- 重工批在第二次品檢又不合格時怎麼處理？重工次數有沒有上限？（CL-003）
- 主批已通過最終品檢後，重工批才完成，此時併回點是什麼？工單是否已結案？（CL-004）
- 兩個終端同時對同一站按「開始」時，誰成功、失敗方看到什麼？（CL-005）
- 「部分不合格」是獨立的判定值與獨立的看板狀態，還是「不合格」的子情況？（CL-006）
- 品檢站被退回的來源站正在被另一批次佔用時，如何排隊？（CL-007）
- 畫面層級的未定項另見 [spec-screens.md](spec-screens.md) 第 12 節，共 10 項，不在此重複。

### Key Entities

| 實體 | 代表什麼 | 關鍵屬性與關係 |
| --- | --- | --- |
| **產品** | 被生產的品項 | 產品代碼、名稱；對應一份製程定義 |
| **製程定義** | 一項產品要經過哪些工序、順序為何 | 有序的工序清單；工序順序來自此處而非程式（FR-006） |
| **工序** | 製程中的一個環節 | 名稱、類型（生產／品檢）、所屬站點、是否回報數量 |
| **站點** | 現場的實體工作位置 | 名稱、綁定的工位終端、對應作業員；同時只能有一張工單進行中（FR-004） |
| **工單** | 一次生產任務 | 工單號、產品、計畫數量、狀態、完工數量；擁有一或多個批次 |
| **批次** | 工單內獨立推進的數量單元 | 類型（主批／重工批／報廢批）、數量、當前工序；重工批與主批獨立推進（FR-022） |
| **工序紀錄** | 某批次在某工序的一次執行 | 次數（第 N 次）、開始／結束時間戳、作業員、欄位值集合、綁定的欄位版本；只增不覆蓋（FR-015） |
| **記錄欄位定義** | 某工序要記錄什麼 | 欄位代碼、顯示名稱、資料型別、是否必填、適用工序、驗證範圍、啟用狀態 |
| **欄位版本** | 欄位定義的某一次快照 | 版本識別、生效時點；工序紀錄綁定其一以確保歷史正確呈現（FR-034） |
| **品檢判定** | 一次品檢的結果 | 判定值、抽檢數、合格數、重工數、報廢數、不良代碼、報廢原因、退回工序 |
| **不良代碼／報廢原因** | 可設定的代碼清單 | 代碼、顯示名稱、啟用狀態；由流程管理員維護（FR-037） |
| **報廢審核** | 超門檻報廢的簽核單 | 關聯工單與品檢判定、送審時點、審核者、結果、駁回理由 |
| **使用者／角色** | 操作者及其權限 | 姓名、角色（作業員／檢驗員／線長／流程管理員）、所屬站點 |
| **料件庫存** | 跨工單銜接的可用量 | 料件代碼、可用量；下游工單開工前檢查（FR-026） |

## Assumptions

以下為規格未明言、但實作與展示所依據的前提。標「待業界核對」者需由 [spec-mvp-industry-check.md](spec-mvp-industry-check.md) 的回收結果確認。

1. 工位終端為固定綁定單一站點的觸控裝置，一台終端只服務一個站點。
2. 作業員身分由終端的登入狀態決定，不在每次操作時輸入工號。
3. **整關做完才轉下一站**，不支援生產中途先轉出部分數量（待業界核對）。
4. 同一站的待辦清單通常只有一張單；多於一張時的選單行為未定義（見 [spec-screens.md](spec-screens.md) 第 12 節第 9 項）。
5. 本版為純前端原型，資料存於瀏覽器端，無後端、無資料庫、無 ERP 介接。
6. 網路持續連線；斷線期間的行為不在本版範圍（見 Out of Scope）。
7. 情境六的「治具自動帶值」在本版以模擬方式呈現，非真實設備介接。
8. 產線 A 與產線 B 的數字（10,000 個、2,000 台、5% 門檻）為展示用範例值，非客戶實際參數。
9. 時間戳採用終端本機時間，時區為 Asia/Taipei。

## Out of Scope（本版範圍外）

明列於此的項目**本版不做**。承諾「什麼都能做」是售後糾紛的來源；承諾「這些做、那些不做」才是可交付的。

**流程與排程**

1. 排程與派工——決定哪張單先做、由誰做。本版只推進已存在的工單。
2. 產能負載與交期模擬。
3. 換線與換模的時間管理。

**庫存與帳務**

4. 庫存的實際扣帳與異動。本版僅在下游開工時檢查可用量（FR-026），不做扣帳。
5. ERP／MRP 介接。
6. 成本歸集的財務結轉。報廢成本僅在工單層面標示歸屬（FR-021）。
7. 退貨、退料、退供應商、客訴退回——與「重工／報廢」是不同的事，本版一律不做。

**設備與介接**

8. 治具、量測儀、PLC 的實體介接。情境六為模擬。
9. 條碼／RFID 掃描。
10. 設備稼動率、OEE、停機原因記錄。

**人員**

11. 工時、計件、薪資。
12. 技能矩陣與認證管理。

**系統面**

13. 離線作業與斷線補傳。**現場網路中斷時的行為本版未定義**，需向客戶明確說明此限制可否接受。
14. 報表設計器與使用者自訂匯出格式。本版提供固定的追溯畫面。
15. 多廠區、多語系。
16. 行動裝置與平板的響應式版面。本版針對固定工位終端。

**設定能力的邊界**（對應 FR-037，須誠實告知客戶）

| 管理員自助可做 | 需供應商協助 |
| --- | --- |
| 新增／修改／停用記錄欄位 | 欄位之間的計算式（例如良率自動算） |
| 調整欄位必填、有效範圍、選項清單 | 欄位觸發的自動流程（例如超標自動通知） |
| 調整報廢審核門檻百分比 | 與外部系統（ERP、治具、量測儀）的介接 |
| 調整不良代碼、報廢原因代碼的清單 | 新增一種全新的資料型別 |
| 調整站點與作業員的對應 | 改變工序推進的基本邏輯 |

## A2. 情境一：正常一次過（產線 A）

最單純的一條路。目的是先讓客戶建立「一站一站推進」的心智模型。

### A2.1 王沖壓開工

**他在哪：** 沖壓線旁的工位終端，畫面預設就停在「沖壓線」。

**他看到什麼：** 畫面上半是他這一站的待辦清單，只有一行：

```
MO-FR-27-005 ｜ 金屬前框 ｜ 薄板沖壓 ｜ 10,000 個 ｜ 可開始
```

畫面下半是工序卡，寫著：

```
本關：薄板沖壓
上一關：無
下一關：沖壓品檢
狀態：尚未開始
```

只有一顆可按的按鈕：**開始**。「完成」是灰的，按不下去。

**他做什麼：** 按「開始」。

**系統回什麼：**

```
本關進行中。作業員：王沖壓。開始：08:12:30
```

工序卡狀態變成「進行中」，「完成」按鈕亮起，「開始」變灰。同一時間，牆上的狀態板自動更新為：

**他做什麼：** 沖壓完 10,000 個，按「完成」。

**系統要他填什麼：** 跳出這一站的回報表單。表單內容不是寫死的，是這一站被設定過的欄位：

| 料捲批號 | 文字 | 是 | RC-20260815-A |
| 備註 | 文字 | 否 | （空白） |

**系統回什麼：**

```
本關已完成。下一關是「沖壓品檢」，由「沖壓品檢站」開始。
```

工序卡變「已完成」，這張單從王沖壓的待辦清單消失。

**同時發生了什麼：** 沖壓品檢站的終端上，這張單自動出現在待辦清單，狀態「可開始」。**沒有人需要通知李檢驗**，也沒有人需要把單子拿去給他。

| 平面度 (mm) | 數字（上限 0.35） | 是 | 0.21 |
| 判定 | 單選 | 是 | 合格 |
| 合格數 | 數字 | 是 | 10,000 |
| 重工數 | 數字 | 是 | 0 |
| 報廢數 | 數字 | 是 | 0 |

**系統回什麼：**

```

雷射焊接（陳焊接）、清洗（林清洗）、成品品檢（李檢驗）依序推進，行為與前述相同。

## A3. 情境二：搶跑被擋

這是客戶最在意的「系統到底控不控得住」的第一個證明點。

**發生什麼：** 沖壓才剛完成，還沒品檢。陳焊接想先把焊接站的機台暖起來，跑到雷射焊接站終端按「開始」。

**他看到什麼：** 雷射焊接站的待辦清單上，這張單顯示：

```
MO-FR-27-005 ｜ 金屬前框 ｜ 雷射焊接 ｜ 10,000 個 ｜ 還不能開始
```

**他按了「開始」，系統回什麼：**

```
還不能開始。需先完成「沖壓品檢」。
```

工單狀態**完全沒有改變**。沒有任何紀錄被寫進去，狀態板也沒有跳動。

**規則的本質：** 系統不是「事後稽核發現有人跳站」，是**當下就按不下去**。跳站在這套系統裡不是違規，是**不存在的操作**。

**這一段要對客戶強調的：** 這個順序不是寫死在程式裡的，是產線 B 可以有完全不同的順序、完全不同的站數，因為順序來自製程定義（見附錄 B.1）。

## A4. 情境三：品檢不合格，退回重做

這是整份文件最重要的一段。

### A4.1 李檢驗判定不合格

**他看到什麼：** 沖壓品檢站終端，工序卡「進行中」。

**他做什麼：** 抽檢發現平面度超標，按「不合格」。

**系統要他填什麼：** 表單多了幾個只在不合格時才出現的欄位：

| 欄位 | 型別 | 必填 | 這次填的值 |
| --- | --- | --- | --- |
| 抽檢數 | 數字 | 是 | 200 |
| 平面度 (mm) | 數字（上限 0.35） | 是 | 0.52 |
| 判定 | 單選 | 是 | 不合格 |
| 不良代碼 | 多選 | **不合格時必填** | DEF-FLAT（平面度超標） |
| 合格數 | 數字 | 是 | 0 |
| 重工數 | 數字 | 是 | 10,000 |
| 報廢數 | 數字 | 是 | 0 |
| 退回工序 | 單選 | 是 | 薄板沖壓 |

**系統回什麼：**

```
判定不合格。工單不能結束。請退回「薄板沖壓」重做。焊接尚未開始。
```

### A4.2 退回瞬間，整條線發生什麼

| 位置 | 退回前 | 退回後 |
| --- | --- | --- |
| 薄板沖壓 | 已完成 | **可重做**（回到待辦清單） |
| 沖壓品檢 | 進行中 | 不合格 |
| 雷射焊接 | 還不能開始 | 還不能開始（維持鎖住） |
| 清洗 | 還不能開始 | 還不能開始 |
| 成品品檢 | 還不能開始 | 還不能開始 |

```

**這裡有兩件事要對客戶講明白：**

1. **退回不會刪掉原本的紀錄。** 王沖壓第一次填的模具編號、料捲批號、實際沖壓數，全部保留。系統記的是「第 1 次沖壓」與「第 2 次沖壓」兩筆，不是覆蓋。事後追溯不良原因時，這兩筆的差異就是答案。
2. **後段站點沒有被「解鎖再鎖回去」。** 它們從頭到尾就沒被解鎖過。退回不需要「取消」後段的任何東西，因為後段根本沒開始。

王沖壓換了模具（MD-FR27-05），重做一批，按完成。系統再次把單推到沖壓品檢。李檢驗這次量到 0.19，判定合格。

## A5. 情境四：部分報廢分流

不是所有不合格都要重做。這一段展示數量會在品檢站分岔。

### A5.1 檢驗員做數量分流

**發生什麼：** 沖壓品檢時，李檢驗發現 10,000 個裡面，有一部分邊緣毛邊嚴重、無法重工。

**他填什麼：**

| 欄位 | 值 | 說明 |
| --- | --- | --- |
| 判定 | 部分不合格 | — |
| 合格數 | 9,200 | 直接往下一站走 |
| 重工數 | 500 | 退回薄板沖壓重做 |
| 報廢數 | 300 | 就地報廢 |
| 不良代碼 | DEF-BURR（毛邊） | 報廢與重工共用 |
| 報廢原因 | SCR-UNREPAIRABLE | **報廢數 > 0 時必填** |

**系統驗什麼：**

```
合格數 + 重工數 + 報廢數 必須等於送檢數（10,000）
```

填不對就送不出去，直接在畫面上標紅。

### A5.2 分流後，工單長成什麼樣

系統把一張工單拆成兩條並行的推進線：

```
主批  9,200 個  →  雷射焊接  →  清洗  →  成品品檢
重工批  500 個  →  薄板沖壓（第 2 次）→ 沖壓品檢（第 2 次）→ 併回主批
報廢    300 個  →  結案，不再流動
```

狀態板同時顯示兩行：

```
主批 9,200 個現在可到雷射焊接。
重工批 500 個現在在薄板沖壓，尚未開始。
```

**規則：**

- 主批**不需要等重工批**，可以直接往下走。這是產能的關鍵，客戶會問。
- 重工批完成品檢後，**併回主批當時所在的工序之前**。若主批已經跑到清洗，重工批補進來時要從雷射焊接開始追。
- 工單的完工數量 = 主批合格數 + 重工批最終合格數。這張單的完工數會是 9,200 + 500 = 9,700（假設重工全過），而不是 10,000。
- 報廢的 300 個，成本仍掛在這張工單上，不會憑空消失。

### A5.3 這件事怎麼影響產線 B

`MO-FR-27-005` 最終只完工 9,700 個前框，但產線 B 的 `MO-MON-27-011` 需要 2,000 個前框。9,700 > 2,000，庫存足夠，產線 B 照常開工。

**但如果報廢量大到剩下 1,800 個**，產線 B 的第一站「前框上料組裝」按下「開始」時會被擋：

```
還不能開始。料件 FR-27-BZ-A 可用量 1,800，需求 2,000，短缺 200。
```

**這是跨工單的控管，不是單一產線的事。** 客戶如果只買現場報工，是看不到這一層的。

## A6. 情境五：整單報廢

**發生什麼：** 成品品檢時發現整批鍍層附著力不合格，全數無法出貨。

**檢驗員填什麼：**

| 欄位 | 值 |
| --- | --- |
| 判定 | 不合格 |
| 合格數 | 0 |
| 重工數 | 0 |
| 報廢數 | 9,700 |
| 不良代碼 | DEF-COATING |
| 報廢原因 | SCR-UNREPAIRABLE |

**系統回什麼：** 這一次不是直接結案，而是：

```
報廢數 9,700 已超過本工單允收上限（5%）。
已送出報廢審核，待「線長」核准後生效。工單暫停於「成品品檢」。
```

**為什麼要有這一關：** 報廢是有金額的。低於門檻的報廢由檢驗員當場決定，超過門檻的必須有人簽字。門檻是**廠內管理員可以設定的數字**，不是寫死的。

**線長那邊看到什麼：** 待審清單出現一筆，點進去看得到完整的追溯紀錄（誰做的、哪副模具、哪批料、每一站的量測值）。線長核准後：

```
報廢審核已核准。工單 MO-FR-27-005 結案，完工數量 0，報廢 9,700。
```

**線長也可以駁回：**

```
報廢審核已駁回。理由：建議先送重工評估。
工單退回「成品品檢」，請重新判定。
```

工單回到李檢驗手上，重新判定。

## A7. 情境六：產線 B —— 同一套系統，完全不同的現場

前面幾段都在產線 A。這一段換到產線 B，證明**系統沒有為金屬沖壓寫死任何東西**。

### A7.1 一樣的操作骨架

張組裝在組裝一線的終端，看到的畫面結構跟王沖壓在沖壓線看到的**完全一樣**：待辦清單、工序卡、開始 / 完成按鈕。

他不需要重新學。這是同一套系統。

### A7.2 完全不同的記錄內容

差別在按下「完成」之後跳出來的表單。

**前框上料組裝站：**

| 欄位 | 型別 | 必填 |
| --- | --- | --- |
| 完成台數 | 數字 | 是 |
| 前框批號 | 單選（自動帶入可用批號） | 是 |
| 面板批號 | 文字 | 是 |

**功能測試站（機台自動帶值）：**

| 欄位 | 型別 | 必填 | 來源 |
| --- | --- | --- | --- |
| 測試報告編號 | 文字 | 是 | 治具自動寫入 |
| 亮度 (cd/m²) | 數字（350–450） | 是 | 治具自動寫入 |
| 色差 ΔE | 數字（上限 3.0） | 是 | 治具自動寫入 |
| 判定 | 單選 | 是 | 治具自動寫入，人可覆寫 |

周測試在這一站**幾乎不用打字**。治具測完把值送進系統，他只需要確認送出。若治具值超出範圍，系統自動帶「不合格」，他要覆寫成合格必須填理由。

**外觀檢驗站（需拍照）：**

| 欄位 | 型別 | 必填 |
| --- | --- | --- |
| 判定 | 單選 | 是 |
| 缺陷代碼 | 多選 | 不合格時必填 |
| 缺陷照片 | 照片（可多張） | 不合格時必填 |
| 合格數 / 重工數 / 報廢數 | 數字 | 是 |

吳目檢用終端上的相機直接拍，照片跟這一次的檢驗紀錄綁在一起。

### A7.3 這一段的結論

產線 A 記的是模具、料捲、平面度。產線 B 記的是治具報告、亮度、色差、照片。

**兩條線用的是同一份程式碼。** 差別全部來自設定。

## A8. 情境七：管理員動態新增欄位

這是客戶問「以後我們自己改得動嗎」時，要當場演給他看的一段。

### A8.1 需求怎麼來的

品保部要求：**從下週起，雷射焊接站要記錄氬氣流量**，因為近期焊道品質波動疑似與氣體流量有關。

在沒有 MES 的工廠，這件事是「印一張新表格發下去」。在寫死欄位的系統，這件事是「開需求單給供應商，等下一版」。

### A8.2 管理員做了什麼

廠內流程管理員（品保部王工程師）登入系統設定 → 記錄欄位 → 選擇「雷射焊接」工序 → 新增欄位。

他填的就是這幾格：

| 設定項 | 他填的值 |
| --- | --- |
| 欄位代碼 | `argon_flow` |
| 顯示名稱 | 氬氣流量 (L/min) |
| 資料型別 | 數字 |
| 是否必填 | 是 |
| 適用工序 | 雷射焊接 |
| 有效範圍 | 12 ~ 20 |

按儲存。**全程約三分鐘，沒有開需求單，沒有重新部署，沒有系統停機。**

### A8.3 下一秒發生什麼

陳焊接在雷射焊接站按「完成」，表單上多了一格：

```
氬氣流量 (L/min)  [        ]  必填
```

沒填不能送出。填 25 會被擋：

```
氬氣流量 25 超出有效範圍 12 ~ 20。
```

**這一格從此進入所有追溯報表**，可以查、可以匯出、可以拿來跟不良率交叉分析。

### A8.4 對既有資料的影響（這題客戶一定會問）

| 情況 | 系統行為 |
| --- | --- |
| 新欄位設定前已完成的工序紀錄 | 不受影響，該欄位顯示「—」。**不會被追認為缺漏。** |
| 設定當下正在進行中的工序 | 按「完成」時就會看到新欄位，要填。<br>**[NEEDS CLARIFICATION: CL-001 — 本行與附錄 B.3 的「紀錄綁定建立當下的欄位版本」互相矛盾，須擇一。]** |
| 尚未開始的工序 | 正常適用。 |
| 事後把欄位改成非必填 | 只影響之後的紀錄，已存的值保留。 |
| 事後停用欄位 | 新表單不再出現，**歷史紀錄仍看得到**，報表可查。欄位不會被刪除。 |

**這條規則的用意：** 欄位是可以演進的，但已經發生過的事實不會被改寫。這是稽核能通過的前提。

### A8.5 管理員動得了什麼、動不了什麼

見 Out of Scope 章末的「設定能力的邊界」表。**這張表要誠實給客戶看。** 承諾「什麼都能自己改」是售後糾紛的來源；承諾「這些能自己改，那些要找我們」才是可交付的。

## B.2 退回與報廢規則

| 編號 | 規則 |
| --- | --- |
| R-11 | 品檢站判定「不合格」時，必須指定退回工序。可選範圍為本站之前的所有生產工序。 |
| R-12 | 退回時，被退回工序回到「可重做」，後續工序維持鎖定。 |
| R-13 | 退回不覆蓋原紀錄。系統以「第 N 次」累加，所有次數的紀錄永久保留。 |
| R-14 | 不合格時，「不良代碼」為必填。 |
| R-15 | 品檢判定必須做數量分流：合格數 + 重工數 + 報廢數 = 送檢數。不相等則阻擋送出。 |
| R-16 | 報廢數 > 0 時，「報廢原因」為必填。 |
| R-17 | 報廢數佔比超過設定門檻（預設 5%）時，觸發主管審核，工單暫停於當前工序。 |
| R-18 | 審核核准後報廢生效；審核駁回則工單退回該品檢工序重新判定。 |

| R-20 | 重工批與主批獨立推進，主批不需等待重工批。 |
| R-21 | 重工批完成後併回主批，起始工序為主批當前工序的前一站。 |
| R-22 | 工單完工數量 = 主批合格數 + 各重工批最終合格數。 |
| R-23 | 最終品檢判定不合格且重工數為 0、報廢數等於送檢數者，視為整單報廢，一律走 R-17 審核。 |

## B.3 動態欄位模型

每個記錄欄位由六個核心屬性定義。這六個是刻意收斂過的最小集合，讓管理員三分鐘內設定得完。

| 屬性 | 說明 | 範例 |
| --- | --- | --- |
| 欄位代碼 | 系統內唯一識別，建立後不可改。報表與匯出用這個當欄名。 | `argon_flow` |
| 顯示名稱 | 作業員在表單上看到的字。可隨時改，不影響歷史資料。 | 氬氣流量 (L/min) |
| 資料型別 | 決定輸入方式與驗證邏輯。 | 數字 / 文字 / 單選 / 多選 / 是否 / 日期 / 照片 |
| 是否必填 | 必填則未填不能送出。可設條件必填（例如「僅不合格時必填」）。 | 是 |
| 適用工序 | 這個欄位出現在哪一站。可多選。 | 雷射焊接 |
| 驗證範圍 | 數字型別為上下限；單選 / 多選型別為選項清單。 | 12 ~ 20 |

**版本化規則：** 欄位設定變更時，系統保留變更前的版本。每一筆工序紀錄綁定它被建立當下的欄位版本，因此歷史資料永遠能正確呈現，不會因為後來改了設定而顯示錯亂。

> **[NEEDS CLARIFICATION: CL-001]** 「被建立當下」指按「開始」或按「完成」？附錄 A8.4 說進行中的工序按「完成」時會看到新欄位，若紀錄在「開始」時即綁定版本，兩者矛盾。須擇一並同步修正 A8.4 與本節。

**停用而非刪除：** 欄位只能停用，不能刪除。停用後新表單不再顯示，歷史紀錄與報表照常可查。

## B.4 狀態機

**工序狀態：**

```
尚未開始 ──開始──▶ 進行中 ──完成/合格──▶ 已完成
                      │
                      └──不合格──▶ 不合格 ──▶（前站轉為「可重做」）

尚未開始 ◀──（前站未完成）── 還不能開始
已完成 ──（被後站退回）──▶ 可重做 ──開始──▶ 進行中
```

**工單狀態：**

```
待生產 ──首站開始──▶ 進行中 ──末站品檢合格──▶ 已結案
                        │
                        ├──報廢超門檻──▶ 待審核 ──核准──▶ 已結案（報廢）
                        │                     └──駁回──▶ 進行中
                        └──料件短缺──▶ 暫停（等料）
```

**站點看板狀態：**

| 狀態 | 顯示 | 意義 |
| --- | --- | --- |
| pending | 尚未開始 | 前站未完成，鎖定中 |
| ready | 可開始 | 輪到這一站了 |
| running | 進行中 | 有人正在做 |
| done | 已完成 | 這一站過了 |
| failed | 不合格 | 品檢判退 |
| rework | 可重做 | 被後站退回，等待重做 |

> **[NEEDS CLARIFICATION: CL-006]** 附錄 A5.1 使用判定值「部分不合格」，但本節看板狀態沒有對應項。部分不合格時該站應顯示哪一個狀態？是否需要新增第七個狀態？
